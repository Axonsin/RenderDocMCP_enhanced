# Unity URP 重建方法

## 1. 取证清单（重建的输入面)

按对象家族收集，每项记录来源 action 与资源：

- **几何**：网格摘要 → 分页数据或 CSV 导出（含实例数与逐实例属性）；拓扑与包围盒
  用于导入后对账。
- **纹理**：绑定槽位 → 采样状态（filter/wrap）→ 导出（记录数值域与格式）；通道
  语义（颜色/法线/遮罩/高度）按 Shader 采样代码确认，不按文件名猜。
- **常量与材质参数**：按绑定展开常量树，映射到 PBR 语义（基色、金属度、粗糙度、
  emissive、alpha 裁剪阈值）；映射关系标注 `inferred`。
- **观测 Shader**：反汇编识别活跃分支、关键字组合、缓冲布局——这决定哪些 URP 标准
  功能够用、哪些要写 Shader。

## 2. 还原结构规划（含默认范围）

先分类，再动手。默认（无调用参数）只做**标准静态场景重建**：下表标 `需 --effects`
或 `需 --pipeline` 的行仅在调用带对应参数时执行；未带参数时这些机制一律记为
"未还原——需参数"，不自行实现。

| 捕获中的机制 | URP 对应 | 默认? | 备注 |
|---|---|---|---|
| 标准光照/阴影 | URP 内置（Main Light、Additional、Shadow Cascade） | 默认 | 参数从常量拟合 |
| 屏幕空间效果（Bloom/Fog/色调映射） | URP Volume 参数 | 默认 | 数值从后处理常量读；只调 Volume，不动渲染器资产 |
| 材质级外观（含自定义材质 Shader） | Lit/Complex 材质 + 自定义 .shader | 默认 | 数学移植分级见 §4 |
| 粒子/拖尾 | Particle System / VFX Graph | 需 `--effects` | 观测发射器行为拟合 |
| Compute 驱动（粒子模拟、裁剪） | 自定义 Compute + GraphicsBuffer | 需 `--effects` | 先复刻数据流再复刻数学 |
| 引擎自定义 Pass（自定义混合、多 pass 材质） | Renderer Feature + Blitter/自定义 Pass | 需 `--pipeline` | 逐 Pass 移植观测行为 |

共享逻辑（多个 Pass 复用的函数、公共缓冲）按功能抽成共享 include/类，不做复制粘贴。
带 `--pipeline` 时，是否引入 Renderer Feature 的判据：效果跨对象/跨 Pass 生效才用；
单对象效果优先用材质/粒子内建机制解决。

## 3. 材质拟合

- 从常量快照推导材质参数：标准 Lit 走 URP 材质参数（Base Map/Metallic/Smoothness 等），
  自定义着色走对应 Shader 的参数；透明（blend、裁剪、排序）、双面、ZTest/ZWrite 等
  状态从管线状态的对应阶段读取，不猜。
- 贴图数值域按四层分别判断，不得跨层等同：
  ① **源格式**——工具响应的 `color_space` 只说明源纹理的存储色彩域，不证明导出文件
  里实际保存的数值；② **导出转换**——导出过程可能做解压/归一化，是否发生取决于
  格式路径；③ **文件编码**——PNG 等常规图片按显示域编码，DDS 可能保留原始格式
  数据；④ **引擎解码**——Unity 贴图导入的 sRGB 开关决定最终采样值。
  链路中任何一层不确定时，做小样本核验：从捕获侧读到几个已知像素的原始数值，与
  导入后同位置采样值对比，确认没有重复解码或漏解码，再批量套用。
- 拟合结果先在单对象上与捕获对照（同视角渲染），再批量套用到同材质家族。

## 4. 自定义 Pass 移植（仅 `--pipeline`）

仅当调用带 `--pipeline` 参数时执行本节；未带参数时相关 Pass 一律记为
"未还原——需参数"。

1. 从捕获确认该 Pass 的输入/输出目标、视口、清屏状态、混合状态、Shader 阶段。
2. 在 Renderer Feature 中复刻执行顺序（注入点对齐原 Pass 在帧中的位置）。
3. Shader 按观测分支实现，常量用 MaterialPropertyBlock/Volume 暴露。数学移植分级：
   有可靠 shader 源码或可读的反编译表达时，**优先逐段保留计算与分支语义**（精度
   最高且可复核）；证据不足或用户明确允许近似时，才从观测行为拟合，并把拟合与原
   实现的差异写进报告。
4. 每个自定义 Pass 独立开关，方便 A/B 对照。

## 5. 验证

- 编译 → 打开场景 → 渲染对照，三级各自通过；控制台报错逐条处理或解释。
- 对照方法：与捕获同视角、同分辨率渲染，对比结构、剪影、颜色域、特效时序
  （特效类多抓几帧对比形态变化）。
- 差异说明逐项给出：现象、原因（近似/未观测分支/引擎私有细节）、影响评估。

## 6. 常见失败模式

| 症状 | 优先怀疑 |
|---|---|
| 编译错误堆积 | 目标 Unity/URP 版本与 API 差异；先对齐模板再写功能 |
| 场景打开缺资源 | 导入路径/域处理、资源未入清单 |
| 画面整体偏暗/偏亮 | 颜色空间（Linear/Gamma）、色调映射、贴图域 |
| 特效形态不对 | 观测分支取错、模拟参数未从常量拟合、执行顺序错 |
| 性能远差于原帧 | 过度通用化（每对象独立 Pass）、未批处理——属优化范畴，先正确后性能 |
