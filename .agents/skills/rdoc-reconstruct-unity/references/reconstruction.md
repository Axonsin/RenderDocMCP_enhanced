# Unity URP 重建方法

## 1. 取证清单（重建的输入面)

按对象家族收集，每项记录来源 action 与资源：

- **几何**：网格摘要 → 分页数据或 CSV 导出（含实例数与逐实例属性）；拓扑与包围盒
  用于导入后对账。
- **纹理**：绑定槽位 → 采样状态（filter/wrap）→ 导出（记录数值域与格式）；通道
  语义（颜色/法线/遮罩/高度）按 Shader 采样代码确认，不按文件名猜。
- **常量与材质参数**：按绑定展开常量树，映射到 PBR 语义（基色、金属度、粗糙度、
  emissive、alpha 裁剪阈值）；映射关系标注 `inferred`。
- **观测 Shader**：反汇编识别活跃分支、关键字组合、缓冲布局——这决定哪些 URP 标准
  功能够用、哪些要写 Shader。

## 2. 还原结构规划

先分类，再动手：

| 捕获中的机制 | URP 对应 | 备注 |
|---|---|---|
| 标准光照/阴影 | URP 内置（Main Light、Additional、Shadow Cascade） | 参数从常量拟合 |
| 粒子/拖尾 | Particle System / VFX Graph | 观测发射器行为拟合 |
| 屏幕空间效果（Bloom/Fog/色调映射） | URP Volume | 数值从后处理常量读 |
| 引擎自定义 Pass（自定义混合、多 pass 材质） | Renderer Feature + Blitter/自定义 Pass | 逐 Pass 移植观测行为 |
| Compute 驱动（粒子模拟、裁剪） | 自定义 Compute + GraphicsBuffer | 先复刻数据流再复刻数学 |

共享逻辑（多个 Pass 复用的函数、公共缓冲）按功能抽成共享 include/类，不做复制粘贴。
是否引入 Renderer Feature 的判据：效果跨对象/跨 Pass 生效才用；单对象效果优先用
材质/粒子内建机制解决。

## 3. 材质拟合

- 从常量快照拟合 Principled 参数；透明（blend、裁剪、排序）、双面、ZTest/ZWrite
  等状态从管线状态的对应阶段读取，不猜。
- 贴图数值域：颜色贴图按 sRGB 导入，数据贴图保持线性；导出侧的颜色域标注是唯一
  依据，换格式/换捕获重新确认。
- 拟合结果先在单对象上与捕获对照（同视角渲染），再批量套用到同材质家族。

## 4. 自定义 Pass 移植

1. 从捕获确认该 Pass 的输入/输出目标、视口、清屏状态、混合状态、Shader 阶段。
2. 在 Renderer Feature 中复刻执行顺序（注入点对齐原 Pass 在帧中的位置）。
3. Shader 按观测分支实现，常量用 MaterialPropertyBlock/Volume 暴露；
   数学不从反汇编逐条翻译，从观测行为拟合，差异写进报告。
4. 每个自定义 Pass 独立开关，方便 A/B 对照。

## 5. 验证

- 编译 → 打开场景 → 渲染对照，三级各自通过；控制台报错逐条处理或解释。
- 对照方法：与捕获同视角、同分辨率渲染，对比结构、剪影、颜色域、特效时序
  （特效类多抓几帧对比形态变化）。
- 差异说明逐项给出：现象、原因（近似/未观测分支/引擎私有细节）、影响评估。

## 6. 常见失败模式

| 症状 | 优先怀疑 |
|---|---|
| 编译错误堆积 | 目标 Unity/URP 版本与 API 差异；先对齐模板再写功能 |
| 场景打开缺资源 | 导入路径/域处理、资源未入清单 |
| 画面整体偏暗/偏亮 | 颜色空间（Linear/Gamma）、色调映射、贴图域 |
| 特效形态不对 | 观测分支取错、模拟参数未从常量拟合、执行顺序错 |
| 性能远差于原帧 | 过度通用化（每对象独立 Pass）、未批处理——属优化范畴，先正确后性能 |
