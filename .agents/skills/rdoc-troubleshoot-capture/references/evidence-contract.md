# 证据与状态契约（共用）

所有 RenderDoc 取证类工作共用本契约。目的：让每一个进入下游构建或报告的结论都能回溯到
原始工具输出，并让"数据不可信"的情形显式暴露，而不是被静默消费。

## 1. 基础记录字段

每条进入报告或下游工程的关键证据，记录以下字段（缺失的写 `null`，不要省略字段）：

| 字段 | 说明 |
|---|---|
| `capture` | 捕获文件路径与内容哈希、加载代次（重新打开过即递增） |
| `runtime` | 扩展版本、RenderDoc 版本、IPC 协议版本、图形 API、回放设备（本地/远端） |
| `event` | 作用的 action 事件（EID 或范围）与查询时的回放位置 |
| `resource` | 资源标识与子资源（mip/slice/sample/depth_slice） |
| `request` | 工具名与参数（含分页 offset/limit） |
| `raw` | 原始输出：导出文件路径或摘要，不手工转写数值 |
| `source` | `tool_output` / `derived`（由原始输出推导）/ `external`（用户或外部资料） |
| `status` | `verified`（实测验证）/ `inferred`（有依据的推断）/ `unresolved`（未解决） |

原始证据与推导数据分开存放（如 `evidence/` 与报告正文），推导必须注明由哪些原始条目推导。
完整常量证据必须来自默认 `export_constants=True` 的导出产物（保留事件、类型、布局、
原始字节和解码值）；纹理 auto/file 响应记录返回的 path 与 `metadata_path` 并核验哈希，
不要求 `content_base64` 恒存在。

## 2. 数据可信度判定

`success` 或"请求没有报错"不等于数据可信。遇到以下情形先判定再消费：

- **空结果两义性**：空常量树、空绑定列表、空网格属性，既可能是合法空（该绑定点确实无
  内容），也可能是回放/驱动异常的占位。结合该资源的其他使用点、Shader 反汇编中的实际
  引用来交叉判断；无法区分时标记 `unresolved`，不得直接进入下游构建。
- **全零数据**：全部为零的字节可能是合法的（清零过的渲染目标、占位纹理），也可能是故障
  症状。不自动认定工具故障，也不未经验证当完整真值；对照渲染预览或多次独立读取复核。
- **颜色与数值域**：记录每次纹理导出的数值域说明（如 `color_space`）。不把某一个案例的
  导出域经验推广成所有捕获的统一颜色处理规则；换捕获、换格式都要重新确认。
- **未知布局**：纹理数值的未知布局（`layout_available=false`）只保留原始导出，
  不得猜测解码。
- **解码缺陷**：怀疑解码/导出存在缺陷时，优先记录版本与最小复现，而不是就地修补数据。
  确需修正导出数据时，保留原始数据、修正算法与适用版本范围，供复核。

## 3. 有状态操作（回放与替换）

查询可能移动回放位置，Shader 替换只在当前捕获会话内有效。约定：

- 操作前记录起始状态（当前事件、已存在的替换清单）。
- 只撤销本次会话中自己创建的替换；保留用户或先前会话已有的替换。
- 无法恢复到起始状态时，明确报告当前状态与差异，不要声称"已还原"。
- 长程任务的每批操作后，重新核对回放健康与位置，再决定是否沿用旧快照。
- 会话代次：所有服务共享 `capture_session`/`replay_revision`；shader 编辑器自身代次
  是独立的 `edit_session`。重开捕获后两者与 binding_id、旧作业一起失效。

## 4. 失败处理

- 同一请求失败后，先确认失败原因是否变化（错误消息、健康状态）；原因未变就停止重复
  请求，保存日志，转做不依赖该数据的工作。
- 断连/回放失效时先 `get_replay_diagnostics` 取本机诊断包取证；设备日志只有用户要求
  或明确同意采集时才设置 `include_device_logs=True`。
- 不把通过 UI 或原生脚本补取的结果记成纯 MCP 成功；来源如实标注。
- 每次失败记录：请求、错误码/消息、当时的健康状态、已尝试次数。

## 5. Checkpoint（长程任务）

跨会话或上下文压缩的长程任务，维护机器可读 checkpoint（JSON），包含：已覆盖的对象/Pass、
建立的映射（资源↔产物）、未解决项、下一批目标、相机与颜色契约、当前事件、本次会话创建
的替换清单。

**恢复规则**：续接后先重新核对捕获哈希/加载代次与健康状态，一致才恢复工作；任何替换、
重新加载之后，相关的旧快照与缓存一律失效，不得只凭资源标识命中旧数据。
