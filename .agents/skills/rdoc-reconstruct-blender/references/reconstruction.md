# Blender 重建方法

## 1. 坐标、轴向与单位

- 先确定捕获侧的世界坐标约定（引擎不同：Y-up/Z-up、左手/右手、单位是米还是厘米），
  再确定 Blender 侧（默认 Z-up、右手、米）。转换矩阵写进 `context.json`，全程只用
  这一个矩阵，不在对象间各自为政。
- 相机恢复：从捕获的视口/相机常量推导 view-projection，反解出位置与朝向后，先摆相机
  渲一张与捕获同视角的图做对照，再谈"还原正确"。
- 验证手法：用包围盒、已知对称结构、地面/墙面等参考面检查缩放与朝向；单点数值对不上
  时先怀疑矩阵约定（行主序/列主序、乘法方向）而不是逐顶点修。

## 2. 实例与去重

- 同一网格被多个实例引用是常态：按顶点缓冲资源标识与绘制参数（instance 数、逐实例
  属性）识别实例族，Blender 侧用链接副本/集合实例表达，不要复制成独立网格。
- 跨 Pass 去重：同一物体在阴影、主渲染、后处理中出现多次；按"几何来源"归并，
  记录它出现在哪些 Pass，交付清单里注明。
- 逐实例差异（位置、颜色 tint、可见性）来自 per-instance 属性：按实例索引读取并在
  Blender 侧逐实例应用；实例寻址与实例数上界遵循工具响应，不要猜。

## 3. 网格数据导出与导入

- 先读网格摘要（拓扑、数量、属性表、包围盒），和导出结果对账：顶点数/索引数一致、
  包围盒量级合理，再进 Blender。
- 分页读取大网格（每页数百顶点量级）；或直接用网格导出工具落 CSV（含索引 sidecar），
  再用 Blender 侧脚本从文件构建网格——几何不经过对话上下文。
- 导入后抽查：随机顶点位置 vs 导出值、三角形数、法线方向（含归一化语义的属性要在
  导出侧确认解码正确）。

## 4. 纹理与材质

- 纹理导出记录数值域标注（sRGB/线性）与格式；颜色贴图与数据贴图（法线、遮罩）的
  域分别对待，Blender 侧节点不要重复解码。
- 材质拟合从捕获常量与纹理绑定推导 PBR 参数（基色、金属度、粗糙度、透明、双面），
  用 Principled BSDF 起步；每个拟合参数标注 `inferred`。
- 观测 Shader 分支复杂的对象：首版用常量快照下的"该分支"拟合，分支差异列为未解决项，
  不要试图在 Blender 里复刻整套 Shader 逻辑。

## 5. 与 Blender MCP 的交接

- 建场景走 Blender MCP（创建对象、设置变换、材质节点、相机、灯光）；确认其工具
  能力后再排步骤，能力缺口（如复杂修改器）用 Blender 文本脚本补，并注明。
- 大批量对象用脚本循环而非逐个调用；每次批量操作后核对场景统计（对象数、网格数）
  与预期一致。
- 渲染对照：与捕获同视角渲染时，匹配相机参数与分辨率；自由视角渲染用于人工检查
  朝向与结构；两组图都存 `assets/` 并在报告中引用。

## 6. 常见失败模式

| 症状 | 优先怀疑 |
|---|---|
| 画面全黑/全白 | 纹理数值域、全零导出、灯光/曝光差异 |
| 模型碎裂或错位 | 索引基址、顶点偏移、实例寻址、坐标系 |
| 颜色对不上 | sRGB 双重解码、通道顺序（BGRA）、顶点色语义 |
| 比例怪异 | 单位（厘米/米）、非统一缩放、父级变换丢失 |
| 部分对象缺失 | 跨 Pass 去重误删、实例族识别漏、视锥/可见性裁剪 |
