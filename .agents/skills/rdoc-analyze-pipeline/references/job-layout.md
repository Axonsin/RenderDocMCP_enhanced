# 输出目录与报告契约（共用）

## 1. 何时建工作目录

跨多阶段（取证→导出→构建→渲染→对照）或涉及生成工程文件的任务，在**用户指定或协商的
输出位置**建立独立工作目录。小问题只返回相关证据与结论，不建目录、不产生空占位结构。

用户明确要求在既有工程内修改时，尊重其工程与版本管理边界，不强行把资产搬进工作目录。

## 2. 目录结构（按需创建）

```text
job/
  context.json             目标范围、模式、运行版本、工具与渲染契约
  checkpoint.json          可恢复进度（见证据契约 §5；不是假定有效的全局状态）
  evidence/                原始工具结果与来源标注
  exports/                 导出的几何/纹理/Shader 等中间资产
  project/                 目标工程文件，或对既有工程的改动清单
  report.md                交付报告
  assets/                  报告引用的 PNG 等图片
  telemetry.jsonl          每次工具调用的记录（一行一条）
```

## 3. 文件职责

- `context.json`：任务范围（哪些对象/Pass/效果）、捕获与运行版本、商定的渲染与颜色
  契约。任务开始时写，范围变更时更新。
- `telemetry.jsonl`：工具名、参数摘要、结果规模、耗时、失败与重试。用于复盘调用效率，
  不用于自证成功。
- `evidence/`：工具原始输出（导出文件、响应摘要），按证据契约标注来源与状态。

## 4. 报告规范（report.md）

报告必须区分以下五类内容，用小节或标注分开，不得混写：

1. **事实**：有原始证据直接支撑的观察。
2. **推断**：由事实推导的结论，注明推导链。
3. **实测**：实际运行验证的结果（含验证方式与环境）。
4. **建议**：可选的后续动作。
5. **未解决项**：`unresolved` 证据、失败尝试、能力缺口。

其他硬性要求：

- 图像相似度等指标只描述本次测量的差异，不换算成"还原百分比"。
- 缺失的数据（Token、费用、计时、某项测量）写 `null` 并说明缺失原因，不估算填充。
- 每个关键结论能通过 `evidence/` 中的条目回溯。
