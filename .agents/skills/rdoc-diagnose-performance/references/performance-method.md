# 性能诊断方法

## 1. 计时解读

- 先确认计时可用性（计时接口的 `available` 标志与错误说明）；不可用时降级为结构
  推断，全程 `inferred` 标注。
- 计时排序要归组：draw 级耗时聚合到 marker/Pass 层再看头部，避免被大量小 draw 干扰
  排序判断。
- 单帧单次回放的样本不构成统计：结论用"本次捕获中"限定，不外推为游戏整体瓶颈。
- 本地回放与远端/不同 GPU 的计时不可比；换设备后旧数据只作参考。

## 2. 瓶颈类别与取证方法

| 类别 | 取证方法 | 佐证信号 |
|---|---|---|
| 过绘制 | 统计同一输出目标上的 draw 覆盖（全屏/大视口 pass 数量、无深度写入的叠加层）；结合输出纹理尺寸 | 目标被多次完整写入；透明/粒子链长 |
| 采样冗余 | 追踪纹理整帧使用：同一资源在邻近 pass 反复作为输入；对照绑定与实际引用的 shader 代码 | 绑定次数远超逻辑需要；同 mip 反复读 |
| 带宽 | 头部 pass 的输入/输出目标尺寸×格式×读写次数估算流量；注意 MSAA 与多 slice | 大分辨率 R32F/多目标；resolve/copy 链 |
| 几何负载 | 网格摘要的顶点/索引数 vs 输出覆盖（小屏幕上画高模）；实例数 | 顶点重但裁剪后贡献小 |
| 状态冗余 | 相邻 draw 的管线 diff：未变化的重复绑定、重复清屏、无效果的 barrier | diff 大量空变化 |
| Pass 级浪费 | marker 汇总显示目标被写入但从未被采样（追踪下游零消费） | 写了没人读 |

## 3. 假设模板

每条假设按此结构写，保证可证伪：

```text
H-<n>：<一句话假设>
证据：<计时/追踪/绑定数据，含 evidence 引用>
适用条件：<在什么前提下成立>
预期收益：<量级估计与不确定性来源；无依据时写"待测"并给验证方法>
反证检查：<如果假设成立，哪些测量应不同；实际测量结果>
验证方式：<需要的额外测量，如 A/B 关闭该 pass / 替换简化 shader>
状态：verified / inferred / needs-measurement
```

## 4. 反证检查的常用手段

- **A/B 替换**：临时替换/简化嫌疑 Shader 或跳过嫌疑 Pass（遵循证据契约的有状态操作
  规则：记录起始状态、只撤销自己的替换），对比计时变化。收益以实测为准；按当前授权
  执行——已授权直接做，未授权先给方案再问一次。
- **下游零消费检查**：追踪嫌疑目标的整帧使用，确认它是否真的影响最终输出。
- **负载守恒检查**：如果去掉某 pass 总耗时几乎不变，说明它不是瓶颈或被别的环节
  掩盖（带宽/同步）——记录而不是忽略这个矛盾。

## 5. 报告结构建议

1. 头部耗时表（Pass/Draw 聚合，含占比）；
2. 假设清单（按优先级 = 预期收益 × 证据强度排序）；
3. 单帧分析无法回答的问题清单（跨帧机制、CPU 瓶颈、设备差异）；
4. 建议的下一步（哪些 A/B 最划算、需要什么授权）。

低质量地少调用不等于高效率：为定位瓶颈多做的追踪与对照查询是合理成本，记录在
telemetry 即可。
