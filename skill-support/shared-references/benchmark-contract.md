# 模式与测评边界契约（共用）

## 1. 两种模式

`mode: practice | benchmark` 是**本 Skill 包自拟的工作字段**，不是任何客户端官方的
frontmatter 字段。写在 `job/context.json` 中：

- **practice（默认）**：服务于当前用户的实际目标。允许在用户授权范围内使用 MCP 之外的
  辅助（API、UI、源码阅读），但必须在证据与报告中标注来源和原因。
- **benchmark**：仅在**外部运行配置显式声明**时进入。此时以运行配置声明的公开输入与
  工具为唯一来源，固定版本与输出契约，输出写入指定目录。

**禁止静默降级**：缺少正式运行契约时，不得把 practice 的产出标注为正式测评成绩；
benchmark 进行中不得改用契约之外的来源补数据。

## 2. benchmark 模式附加约束

- 纯 MCP 赛道：不得绕过 MCP 用 UI、原生脚本或文件系统直读捕获；缺少能力时记录失败或
  覆盖缺口，而不是变通绕过。
- 使用固定的输出契约与独立输出目录；不因结果好坏调整渲染/转换设置。
- 保留完整工具日志：错误、重试、阶段耗时、Skill 与工具版本。
- 结果交给外部裁判与既有 harness 评定；**不在本 Skill 内生成正式得分**。

## 3. 裁判素材边界

裁判量表、源码映射、参考工程、正确答案不属于 Skill 包，永远不出现在 Skill 文本、
references 或 scripts 中。候选工作区不得从包含答案的私有目录启动。

## 4. 与本包其他部分的关系

- 触发/行为用例保存在包的 `evals` 集合中，只包含通用场景，不含任何具体捕获的答案。
- practice 模式下本契约仅约束"如实标注来源"；其余按用户目标行事。
