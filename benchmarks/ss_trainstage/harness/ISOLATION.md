# 正式运行前的隔离与回放验收

当前目录是裁判工作区，当前宿主已记录隔离失败。公开ZIP的白名单导出验证只证明打包内容，不证明候选运行环境安全。首版不创建模型会话、不安装虚拟机，也不自动执行模型跑批。

正式运行应使用独立机器或由外部管理的虚拟机/受限账户环境，只提供公开输入包、选定MCP版本、相同下游工具和空输出目录。源码、oracle、reference、裁判历史、凭据和包含答案的报告不得挂载。账户或文件权限策略需由独立管理者验证；仅改变工作目录或在提示词中禁止读取不构成隔离。

隔离同时覆盖模型Shell和所有工具后端。特别是Blender MCP的Python执行、RenderDoc扩展、浏览器/文件工具与任意代码工具，不能通过仍运行在裁判账户下的服务读取私有数据。不能把本次已加载参考工程的Blender实例交给正式候选。需要独立干净的Blender进程、空场景和独立MCP连接。

在实际候选环境内执行路径预检，以下路径由主办方按真实部署填入：

```powershell
python isolation_check.py --forbid PRIVATE_SOURCE --forbid PRIVATE_ORACLE --forbid PRIVATE_REFERENCE --out isolation-result.json
```

该脚本只测试给定路径，不能证明其他路径别名、网络共享、凭据或其他工具无法读取。通过这一步后，独立裁判仍需记录实际账户、共享/挂载、服务身份和工具权限核验；未知状态维持not_checked，不能取得正式分。

每次运行之前，主办方还需核验选定Local或远端环境：输入RDC哈希、实际加载状态、API、GPU/驱动、可读Action、关键纹理与最终画面。设备变化后建立新的条件ID，不能继承另一设备的GPU时间。记录冷/热启动以及捕获是否预先加载。使用待测MCP本身确认健康；如果它不支持该回放方式，应记录失败，不能由裁判UI补齐候选取证能力。

本次实际取证使用的已安装RenderDoc旧扩展与当前仓库接口不同，版本和文件摘要保存在oracle/evidence/environment.json。后续比较必须锁定实际加载的扩展、服务器和客户端版本，不能仅填写仓库HEAD。Local回放获用户授权，但当前未由裁判重新完成健康检查。

全部预检证据应交给独立裁判，作为submission_validity与independence门槛的依据。首版当前没有正式候选提交；不要把公开包导出、裁判参考构建或路径预检等同于一次有效模型实验。
